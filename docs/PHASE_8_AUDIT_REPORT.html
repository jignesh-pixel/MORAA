Phase 8 Audit Report

Whole backend after Phase 8 (SKU packs, WhatsApp catalogue cart, Google Drive delivery) · branch phase-8-sku-drive · 7–8 Oct 2026 · checked against code and tests only: no real Google, Meta or Razorpay calls were made

Verdict in one paragraph. The money side is solid: a payment adds credits once, a photo uses one credit, a failed image gives its credit back once, and the books (credit ledger, wallet, invoices) agree. The serious problems the audit found were fixed before this report. Phase 8 is ready for a supervised real-world test with the switches on for test phones only. It is not ready for full public traffic at 100 images a minute: Google's per-drive file limit and the background queue's speed need a decision and some work first (sections 3 and 4). With both new switches off (the default), customers see no change.

3. Findings by business impact

Must decide before full launch

  1. The shared drive fills up at full speed. At 100 images a minute (about 144,000 a day) and 90-day storage, Google's 400,000-item limit is reached in about 3 days; after that uploads fail and everything falls back to WhatsApp. Options: keep images for 1–2 days in Drive (customers download), spread customers over several shared drives, or a different store (Google Cloud Storage, Cloudflare R2). At today's real volume this is far away. Owner + developer.
  2. The background queue is too slow for full traffic. One queue per server handles roughly 25–30 jobs a minute; full traffic needs around 200 (sheet updates, ready messages, uploads). Ready messages would fall behind. Fix: run several jobs at once and update sheets less often. Developer.
  3. Google Sheets limit. About 60 writes a minute per service account; the Usage Logs sheet updates exceed that with 100 active customers a minute. Fix: batch updates. Developer.

Fix soon (not blocking a test launch)

  1. Email typed in chat moves the folder. Any email in any message replaces the stored one and the folder is shared to it (the old one loses access). Add a "Is this your email? Yes / No" step. Owner (wording) + developer.
  2. Drive clean-up during "DELETE MY DATA" is tried once. If Google fails, the folder stays shared; only an alert is logged. Add a retry job. Developer.
  3. A broken Google key delays every image by about 2 hours before the WhatsApp fallback. Test the key at start-up and fall back at once when Google refuses it. Developer.
  4. Drive image deletion after 90 days only runs with RETENTION_ENABLED=true (documented now). The deletion runs one file at a time and would be slow at full volume. Operator + developer.
  5. Customers with both white and Creative credits get the two buttons for each photo (by design), and a Creative pack paid by one credit runs 7 AI calls (by design). Confirm this is what you want. Owner.
  6. Old archive copies in the personal Google account (from before Phase 8, if the archive was ever switched on) are no longer managed; export and delete them by hand. Owner.

Fixed during this audit

  • Pack payments must match a pack link we created (purpose, units, amount), else they are parked for review.
  • Images and invoices go to Drive only when the customer's folder is shared with their email; otherwise WhatsApp as before, and a share is queued.
  • Staff retry refuses orders whose SKU credit was returned.
  • Pack links expire after 48 hours (inside the 3-day payment check window).
  • Credit holders never get the cash bulk prompt.
  • The WhatsApp fallback claims the order first, so two servers cannot send the same image twice.
  • The Drive upload no longer occupies an image-generation slot.
  • An old stuck order no longer blocks a customer's "ready" message forever.
  • Folder sharing is retried correctly when a customer switches back to an earlier email, and emails are no longer stored in queue keys.
  • Photo clean-up on the server stopped after its first batch (an older bug): fixed.
  • Google key files are kept out of git and out of the Docker image.
